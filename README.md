# 네비 도우미 (navi-helper)

FYT 계열 안드로이드 올인원 네비(UIS7870, 안드로이드 13)에서 쓰려고 만든 작은 보조 앱입니다.
화면이 없는 접근성 서비스 하나로 동작하고, 앱 크기는 100KB 정도입니다.
**PC 없이 네비만으로 설치부터 권한 받기까지 할 수 있습니다.** 같은 내용이 앱 안의 **'사용법 · 도움말'** 버튼에도 들어 있습니다.

## 기능

### 1. 티맵 자동 주행
티맵을 **전체 화면으로 켜고** 홈 화면(검색창이 보이는 화면)에 머문 채 정해진 시간(기본 10초) 동안 조작이 없으면,
검색창 옆 **화살표(주행 / 안전운전) 버튼**을 대신 누릅니다. 목적지를 정하지 않아도 지도가 주행 화면으로 바뀝니다.

- 티맵을 만지고 있으면(스크롤, 터치, 검색 입력) 시간을 처음부터 다시 셉니다. 광고 배너가 저절로 넘어가는 건 조작으로 치지 않습니다.
- 기본값으로 **런처 홈 분할 칸 안의 티맵은 건드리지 않습니다.** 분할 칸에서 3D 주행 화면을 계속 그리면 발열이 크게 늘기 때문입니다. 설정에서 켤 수 있습니다.

### 2. 티맵 광고 팝업 자동 닫기
티맵이 켜질 때 뜨는 광고 팝업에 **'오늘은 그만보기'** 류 버튼이 보이면 대신 눌러 닫습니다. 그 글자가 눌리지 않는 팝업이면 같은 팝업의 '닫기'를 누릅니다. 설정에서 끌 수 있습니다.

### 3. 재부팅 뒤 접근성 자동으로 다시 켜기
FYT 시스템이 재부팅이나 시동을 다시 걸 때 접근성 설정을 초기화해 **티맵 자동주행**이 "사용 안 함"으로 돌아가는 경우가 있습니다.
부팅 직후와 10초·30초·90초·3분 뒤에 확인해서 꺼져 있으면 저절로 다시 켭니다. 앱 첫 화면에 마지막으로 다시 켠 시각이 나옵니다.

### 4. 런처 홈 분할 칸 글자 크기(dpi) 조절
FYT 런처(`launcher10001` 등)는 홈 화면 분할 칸에 앱을 띄울 때 별도의 가상 화면을 만드는데,
이 화면의 dpi가 160으로 잡혀 있어서(본 화면은 240) 칸 안의 앱이 아주 작게 보입니다.
이 앱은 런처가 분할 칸 화면을 만들거나 다시 만들 때마다 dpi를 설정값(기본 200)으로 맞춥니다.

## 기능별로 필요한 것

| 기능 | 접근성만 켜면 | adb 권한까지 받으면 |
|---|---|---|
| 1. 티맵 자동 주행 | ✅ | ✅ |
| 2. 광고 팝업 자동 닫기 | ✅ | ✅ |
| 3. 재부팅 뒤 접근성 자동 켜기 | ❌ 꺼질 때마다 직접 켜야 함 | ✅ |
| 4. 분할 칸 dpi 조절 | ❌ | ✅ |

adb 권한(`WRITE_SECURE_SETTINGS`)은 **처음 한 번만** 받으면 재부팅해도 남습니다. 아래 방법 중 하나를 고르세요. **PC가 없으면 Shizuku 방법**을 쓰면 됩니다.

## 설치

1. 네비 브라우저로 [Releases](../../releases)에서 `navi-helper.apk`를 받아 설치합니다.
   - "출처를 알 수 없는 앱 설치"를 허용하라고 나오면 허용합니다.
2. 앱 목록에서 **네비 도우미**를 엽니다. 처음 열면 도움말이 뜹니다.
3. **접근성 설정 열기** → 설치된 앱(또는 다운로드한 앱) → **티맵 자동주행** → 사용.
   여기까지 하면 기능 1, 2가 동작합니다.
4. 기능 3, 4도 쓰려면 아래 방법으로 adb 권한을 받습니다.

## adb 권한 받기 — PC 없이 (Shizuku)

[Shizuku](https://shizuku.rikka.app/)는 안드로이드 11 이상에서 기기가 **무선 디버깅으로 자기 자신에게 접속**하게 해 주는 무료 앱입니다. 이 앱의 **'Shizuku로 권한 받기'** 버튼이 그 연결을 써서 스스로 권한을 받습니다.

1. **개발자 옵션 켜기**: 설정 → 기기 정보(태블릿 정보) → **빌드 번호**를 7번 누릅니다.
   - 판매처에 따라 개발자 옵션에 비밀번호가 걸려 있을 수 있습니다.
2. 네비 도우미에서 **'Shizuku 설치 (플레이스토어)'**를 눌러 Shizuku를 설치합니다.
3. Shizuku를 열고 **'무선 디버깅으로 시작' → '페어링'**을 누릅니다. 알림이 하나 생깁니다.
4. 설정 → 개발자 옵션 → **무선 디버깅** 켜기 → 그 안의 **'페어링 코드로 기기 페어링'**을 누릅니다.
5. 화면의 **6자리 코드**를, 3번에서 생긴 Shizuku 알림을 내려 입력합니다.
   - 설정과 Shizuku를 분할 화면으로 같이 띄우면 편합니다.
6. Shizuku로 돌아가 **'시작'**을 누릅니다. **'실행 중'**이 보이면 성공입니다.
7. 네비 도우미로 돌아와 **'Shizuku로 권한 받기'** → Shizuku 창에서 **'허용'**.
8. 첫 화면에 **"adb 권한: 있음"**이 나오면 끝입니다. 접근성도 자동으로 켜집니다.

끝난 뒤 Shizuku는 지워도 되고, 무선 디버깅도 꺼도 됩니다. 네비를 재부팅하면 Shizuku는 꺼지지만 **받은 권한은 그대로 남습니다.**

## adb 권한 받기 — PC로

네비의 개발자 옵션 → 무선 디버깅으로 PC와 연결한 뒤 한 줄 실행합니다.
```
adb shell pm grant kr.navihelper android.permission.WRITE_SECURE_SETTINGS
```

## 업데이트
[Releases](../../releases)에서 새 `navi-helper.apk`를 받아 **덮어 설치**합니다.
**앱을 지우고 다시 깔면 adb 권한이 사라집니다.** 그럴 땐 권한 받기를 다시 하면 됩니다.

> **1.2.2부터 서명 키가 바뀌었습니다.** 1.2.1 이하의 `navi-helper.apk`를 쓰시던 분은 덮어 설치가 안 되니,
> 예전 앱을 **지우고 새로 설치한 뒤 권한 받기(Shizuku)를 한 번 다시** 해 주세요. 그 뒤로는 다시 덮어 설치로 업데이트됩니다.

## 잘 안 될 때
- **'Shizuku가 실행 중이 아닙니다'**: Shizuku 단계 3~6을 다시 하세요. 재부팅하면 Shizuku는 꺼집니다.
- **페어링 알림이 안 보임**: 화면 위쪽을 내려 알림창을 열어 보세요.
- **자동 주행이 안 됨**: 티맵을 전체 화면으로 켰는지, 홈 화면(검색창이 보이는 화면)에 그대로 두었는지 확인하세요.
- **재부팅 뒤 접근성이 계속 꺼짐**: 첫 화면에 "adb 권한: 있음"인지, "접근성 자동 켜기: 사용"인지 확인하세요.

## 확인한 환경
- FYT UIS7870 (`uis7870sc_2h10`), 안드로이드 13, 2000×1200 / 1920×1200
- 런처: `com.syu.launcher10001`
- 티맵 11.8.x (`com.skt.tmap.ku`)
- FYT UIS7865: 티맵 자동 주행 동작 확인 (사용자 제보, 2026-11). dpi 조절은 아직 확인 못 함

다른 기기, 런처, 티맵 버전에서는 동작하지 않을 수 있습니다. 티맵이 업데이트되어 버튼 구조가 바뀌면 자동 주행이 멈출 수 있습니다.

## 직접 빌드
Gradle 없이 Android SDK 명령줄 도구로 빌드합니다. JDK 17, build-tools 34.0.0, platforms;android-33이 필요합니다.
```
export ANDROID_SDK=/path/to/android-sdk
export KEYSTORE=/path/to/your.keystore   # 없으면 새로 만듭니다
./build.sh
```
`libs/`의 Shizuku API(jar)를 같이 넣어 빌드합니다.

릴리스는 GitHub Actions가 합니다. `v1.2.3`처럼 `v`로 시작하는 태그를 올리면 서명된 APK가 Releases에 붙습니다.
개발·릴리스 절차는 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)를 보세요.

## 어떻게 동작하나
- **자동 주행**: 안드로이드 접근성 API로 티맵 창에서 `com.skt.tmap.ku:id/button_safety_driving` 버튼을 찾아 `ACTION_CLICK`을 보냅니다. 사람이 손으로 누르는 것과 같은 방식이고, 티맵의 코드나 데이터를 수정하지 않습니다.
- **접근성 자동 켜기**: `WRITE_SECURE_SETTINGS`로 `enabled_accessibility_services`에 이 앱의 서비스를 다시 넣습니다. 다른 앱의 접근성 서비스는 건드리지 않습니다.
- **dpi 조절**: 이름이 `Embedded_Task@`로 시작하는 가상 화면이 생기거나 바뀌면 `IWindowManager.setForcedDisplayDensityForUser`로 그 화면의 dpi만 바꿉니다. 본 화면과 다른 앱에는 영향이 없습니다.
- **Shizuku 권한 받기**: Shizuku의 셸 권한으로 `pm grant <이 앱> WRITE_SECURE_SETTINGS`를 한 번 실행합니다. 이 명령 말고는 Shizuku를 쓰지 않습니다.
